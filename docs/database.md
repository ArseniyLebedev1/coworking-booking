# Проектирование базы данных

## СУБД
PostgreSQL

## Основные таблицы

1. roles — роли пользователей.
2. users — пользователи системы.
3. locations — адреса коворкингов.
4. rooms — переговорные комнаты и рабочие места.
5. bookings — бронирования помещений.
6. amenities — удобства и оборудование.
7. room_amenities — связь помещений с удобствами.

## Основные связи

- roles 1:N users
- locations 1:N rooms
- users 1:N bookings
- rooms 1:N bookings
- rooms M:N amenities (через room_amenities)

## Бизнес-правило

Нельзя создавать два активных бронирования одного помещения с пересекающимися временными интервалами.

## Структура таблиц

### users — пользователи

| Поле | Тип данных | Назначение |
|---|---|---|
| id | UUID | Уникальный идентификатор (PK) |
| email | VARCHAR(255) | Email пользователя, UNIQUE |
| password_hash | VARCHAR(255) | Хэш пароля |
| full_name | VARCHAR(255) | Имя пользователя |
| role_id | UUID | Ссылка на roles.id (FK) |
| is_blocked | BOOLEAN | Признак блокировки |
| created_at | TIMESTAMP | Дата регистрации |
| updated_at | TIMESTAMP | Дата изменения |

Ограничения:
- id — первичный ключ.
- email — обязательное уникальное поле.
- password_hash — обязательное поле.
- role_id — обязательный внешний ключ.
- is_blocked — по умолчанию false.
- created_at — по умолчанию текущее время.

### roles — роли пользователей

| Поле | Тип данных | Назначение |
|---|---|---|
| id | UUID | Уникальный идентификатор (PK) |
| name | VARCHAR(50) | Название роли |
| description | TEXT | Описание роли |

Ограничения:
- id — первичный ключ.
- name — обязательное уникальное поле.

Предусмотренные роли:

- guest — просмотр доступных помещений.
- employee — создание и управление своими бронированиями.
- admin — управление пользователями, помещениями и бронированиями.

Связь:
- roles 1:N users — одна роль может быть назначена нескольким пользователям.

### locations — местоположения коворкингов

| Поле | Тип данных | Назначение |
|---|---|---|
| id | UUID | Уникальный идентификатор (PK) |
| name | VARCHAR(255) | Название коворкинга |
| address | VARCHAR(255) | Адрес коворкинга |
| city | VARCHAR(100) | Город |
| description | TEXT | Описание коворкинга |
| created_at | TIMESTAMP | Дата создания |
| updated_at | TIMESTAMP | Дата изменения |

Ограничения:
- id — первичный ключ.
- name — обязательное поле.
- address — обязательное поле.
- city — обязательное поле.
- created_at — по умолчанию текущее время.

Связь:
- locations 1:N rooms — один коворкинг может содержать несколько помещений.

Примечание:
- Незарегистрированный посетитель также считается гостем.
- Доступ к защищённым операциям проверяется на сервере.


### rooms — помещения и рабочие места

| Поле | Тип данных | Назначение |
|---|---|---|
| id | UUID | Уникальный идентификатор (PK) |
| location_id | UUID | Ссылка на locations.id (FK) |
| name | VARCHAR(255) | Название помещения |
| description | TEXT | Описание помещения |
| type | VARCHAR(50) | Тип: meeting_room или workspace |
| capacity | INTEGER | Вместимость |
| is_active | BOOLEAN | Доступно ли помещение для бронирования |
| image_url | TEXT | Ссылка на фотографию |
| created_at | TIMESTAMP | Дата создания |
| updated_at | TIMESTAMP | Дата изменения |

Ограничения:
- id — первичный ключ.
- location_id — обязательный внешний ключ.
- name — обязательное поле.
- type — только meeting_room или workspace.
- capacity — положительное число.
- is_active — по умолчанию true.
- created_at — по умолчанию текущее время.

Связи:
- locations 1:N rooms — один коворкинг содержит несколько помещений.
- rooms 1:N bookings — у помещения может быть много бронирований.
- rooms M:N amenities — помещение может иметь несколько удобств.

### bookings — бронирования помещений

| Поле | Тип данных | Назначение |
|---|---|---|
| id | UUID | Уникальный идентификатор (PK) |
| user_id | UUID | Ссылка на users.id (FK) |
| room_id | UUID | Ссылка на rooms.id (FK) |
| start_time | TIMESTAMPTZ | Начало бронирования |
| end_time | TIMESTAMPTZ | Окончание бронирования |
| status | VARCHAR(20) | Статус бронирования |
| created_at | TIMESTAMPTZ | Дата создания |
| updated_at | TIMESTAMPTZ | Дата изменения |

Ограничения:
- id — первичный ключ.
- user_id — обязательный внешний ключ.
- room_id — обязательный внешний ключ.
- start_time — обязательное поле.
- end_time — обязательное поле.
- end_time должен быть больше start_time.
- status — только confirmed или cancelled.
- status — по умолчанию confirmed.
- created_at — по умолчанию текущее время.

Связи:
- users 1:N bookings — пользователь может иметь много бронирований.
- rooms 1:N bookings — помещение может иметь много бронирований.

Бизнес-правила:
- Только авторизованный сотрудник может создавать бронирования.
- Нельзя бронировать помещение на прошедшее время.
- Нельзя создавать пересекающиеся активные бронирования одного помещения.
- Отменённые бронирования не блокируют временные интервалы.
- Сотрудник может отменять только собственные бронирования.
- Администратор может управлять всеми бронированиями.

Проверка пересечений:
Для одного room_id два бронирования со статусом
confirmed не должны удовлетворять одновременно условиям:

existing.start_time < new.end_time
AND
existing.end_time > new.start_time

Для надёжной защиты от одновременных запросов
необходимо также использовать ограничение
EXCLUDE в PostgreSQL.

### amenities — удобства и оборудование

| Поле | Тип данных | Назначение |
|---|---|---|
| id | UUID | Уникальный идентификатор (PK) |
| name | VARCHAR(100) | Название удобства |
| description | TEXT | Описание удобства |
| created_at | TIMESTAMPTZ | Дата создания |

Ограничения:
- id — первичный ключ.
- name — обязательное уникальное поле.
- created_at — по умолчанию текущее время.

Примеры удобств:
- Wi-Fi
- Проектор
- Телевизор
- Кондиционер
- Маркерная доска
- Видеоконференцсвязь

Связь:
- amenities M:N rooms — одно удобство может
  находиться в нескольких помещениях,
  а одно помещение может иметь несколько удобств.

Связь реализуется через таблицу room_amenities.

### room_amenities — удобства помещений

| Поле | Тип данных | Назначение |
|---|---|---|
| room_id | UUID | Ссылка на rooms.id (FK) |
| amenity_id | UUID | Ссылка на amenities.id (FK) |

Ограничения:
- room_id — обязательный внешний ключ.
- amenity_id — обязательный внешний ключ.
- PRIMARY KEY (room_id, amenity_id) — составной первичный ключ.
- Запрещено повторное добавление одного удобства в одно помещение.

Связи:
- rooms 1:N room_amenities
- amenities 1:N room_amenities

Таким образом реализуется связь M:N
между rooms и amenities.

Пример данных:

| room_id | amenity_id |
|---|---|
| room-1 | wifi |
| room-1 | projector |
| room-2 | wifi |

Примечание:
В примере используются условные обозначения.
В реальной базе данных идентификаторы будут UUID.
