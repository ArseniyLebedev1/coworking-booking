# План проверки MVP перед защитой

## Критерии приёмки

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| T01 | Открыть главную страницу | Каталог загружается, seed-данные видны |
| T02 | Поиск «Атлас» | В каталоге отображается соответствующая переговорная |
| T03 | Фильтр по городу, типу и вместимости | Возвращаются только подходящие помещения |
| T04 | Пагинация `page_size=1` | `items` содержит не больше 1 помещения, `total` корректен |
| T05 | Регистрация валидного пользователя | 201, пользователь создан с ролью employee |
| T06 | Повторная регистрация email | 409 без дубля |
| T07 | Вход с корректным/неверным паролем | 200 с токеном / 401 |
| T08 | Обращение к `/users/me` без JWT | 401 |
| T09 | Создание брони на будущее время | 201; запись видна в личном кабинете |
| T10 | Повторная бронь того же интервала | 409; конфликт предотвращён PostgreSQL |
| T11 | Отмена собственной брони | status=cancelled; интервал вновь доступен |
| T12 | Действия пользователя без admin | 403 для админ-API |
| T13 | CRUD помещений администратором | Создание, изменение, деактивация; корректное отображение |
| T14 | Загрузка фото PNG/JPEG/WebP | Изображение доступно по `/uploads/` |
| T15 | Загрузка невалидного формата | 415 / 413 при превышении 5 МБ |
| T16 | Изменение профиля | Имя сохраняется и отображается в кабинете |
| T17 | Открыть публичный сайт с другого устройства | HTTPS, корректная работа API |
| T18 | Перезапуск контейнеров без `-v` | Бронирования и файлы сохраняются |

## Команды проверки

```bash
docker compose up --build -d
curl -fsS http://localhost:8000/health
curl -fsS 'http://localhost:8000/catalog/rooms?page=1&page_size=1'
docker compose exec -T backend python -m pytest -q tests
```

В GitHub Actions выполняются компиляция Python, тесты, сборка фронтенда и интеграционные сценарии с PostgreSQL. **Тесты T17/T18 и ручные сценарии должны быть подтверждены отдельно на фактическом сервере**; отсутствие проверки не равнозначно прохождению.

## Итог

Сценарии не считаются «пройдены» только по наличию тест-плана. Сохраните скриншоты браузера, результатов Actions и вывода Docker Compose как доказательства для отчёта.
