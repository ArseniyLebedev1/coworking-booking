# Отчёт по учебной практике

**Тема:** Разработка веб-платформы бронирования переговорных комнат и рабочих мест «SpaceBook»

**Репозиторий:** https://github.com/ArseniyLebedev1/coworking-booking

**Плановая трудоёмкость:** 72 часа, 9 дней. 

## 1. Цель и задачи

Цель — разработка полнофункционального учебного MVP для просмотра доступных помещений, регистрации и входа, управления бронированиями с предотвращением конфликтов времени, администрирования и поиска. Требуется изучить моделирование базы данных, REST API, клиентское приложение, миграции, Docker, тестирование и CI.

## 2. Анализ и проектирование (дни 1–2, 16 ч)

Составлены пользовательские истории, ER-диаграмма для 7 таблиц (roles, users, locations, rooms, bookings, amenities, room_amenities), предварительная спецификация OpenAPI. Созданы макеты интерфейса в Figma, настроены репозиторий, kanban-задачи, Docker Compose и базовый CI.

## 3. Разработка ядра (дни 3–5, 24 ч)

Разработаны FastAPI, SQLAlchemy и миграции Alembic. Создано начальное заполнение базы тестовыми коворкингами, помещениями и удобствами. Реализованы хеширование паролей Argon2, JWT-вход, разграничение ролей (RBAC), CRUD локаций и помещений, создание и отмена бронирований. Ограничение PostgreSQL EXCLUDE защищает от пересечения подтверждённых броней одного помещения, включая конкурентные запросы. Создан React-клиент на TypeScript с маршрутизацией.

## 4. Бизнес-логика и интерфейс (дни 6–7, 16 ч)

Разработаны поиск по помещениям и локациям, фильтрация по городу, вместимости, типу и удобствам, серверная пагинация. Администратор может добавлять/изменять/скрывать помещения, загружать фотографии и управлять доступом пользователей. В личном кабинете можно редактировать имя, просматривать бронирования по статусу и отменять их. Разработан дашборд статистики.

## 5. Стабилизация и подготовка к защите (дни 8–9, 16 ч)

Добавлена production-конфигурация Docker Compose с Caddy, автоматическим HTTPS (при правильных DNS и открытых портах), проксированием API, переменными окружения для секретов и постоянными томами БД и изображений. Расширены тестовые сценарии; подготовлены инструкция по развёртыванию, план приёмки и презентация.

**Статус публичного развёртывания:** файл `docs/deployment.md` содержит инструкции. Публичный домен и сервер должны быть предоставлены и развёрнуты отдельно; нельзя считать публичный стенд готовым только на основании коммита.

## 6. Технологии

React 18, TypeScript, Vite, FastAPI, Python 3.12, SQLAlchemy 2, PostgreSQL 16, Alembic, JWT, Argon2, Docker Compose, GitHub Actions, Figma.

## 7. Тестирование

Проверены базовые действия пользователя (регистрация, вход, создание/отмена броней), защита от пересечения интервалов, доступ по ролям, параметры каталога, загрузка изображений и сборка фронтенда. Перечень проверок и ожидаемые результаты приведены в `docs/test-plan.md`. Фактические прогоны GitHub Actions можно посмотреть во вкладке Actions; сценарии публичного сервера требуют отдельной проверки.

## 8. Результаты и ограничения

Сформирован учебный MVP и инфраструктура воспроизводимого локального запуска. Предварительная `docs/openapi.yaml` описывает также планируемые методы, которые реализованы не полностью — актуальный перечень работающих маршрутов доступен по `/docs`. Для промышленной эксплуатации потребуется внешняя инфраструктура, HTTPS на домене, управление резервными копиями и дополнительное усиление безопасности.

## 9. Вывод

Практика позволила пройти полный учебный цикл: анализ требований, проектирование, разработка серверной и клиентской частей, обеспечение целостности данных, CI и подготовка к развёртыванию. Проект демонстрирует применение современных инструментов full-stack разработки.
