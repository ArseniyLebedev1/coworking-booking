# Дни 6–7: бизнес-логика и интерфейс

Развитие MVP согласно календарному плану учебной практики.

## Возможности

- `GET /catalog/rooms`: поиск по названию/описанию/локации; фильтры `city`, `room_type`, `capacity_min`, несколько `amenity_id`; `page`, `page_size`; в ответе `items`, `total`, `pages`.
- `GET /amenities`, `GET /rooms/{room_id}/amenities`: справочник удобств и удобства помещения.
- `PATCH /users/me`: редактирование имени в личном кабинете.
- `GET /admin/stats`: метрики администратора: пользователи, локации, комнаты и бронирования.
- `POST /rooms/{room_id}/image`: загрузка PNG/JPEG/WebP до 5 МБ только администратором с проверкой сигнатуры. Изображения доступны через `/uploads/*`.
- React: фильтры, поиск, пагинация, карточки с изображениями, кабинет с управлением бронированиями, редактирование профиля, панель администратора с управлением помещениями, пользователями и изображениями.

## Локальный запуск (macOS)

Перейдите в скачанный репозиторий. Проверьте файл `.env`, затем выполните:

```bash
docker compose up --build -d
docker compose ps
```

Откройте http://localhost:5173, API — http://localhost:8000/docs.

При обновлении локальной копии из ZIP: сначала остановите контейнеры (`docker compose down`), скачайте свежую версию и перенесите локальный `.env` в новую папку. **Не выполняйте `docker compose down -v`**: он удаляет БД. Если папка проекта и имя Compose изменены, Docker может создать новый volume — для сохранения данных используйте git pull из первоначальной папки.

## Хранение и безопасность

Изображения сохраняются в Docker volume `uploads_data`, а не в Git. JWT и пароли по-прежнему не публикуются. Для загрузки нужен администратор. Публичной регистрации администраторов нет; роль назначается вручную в БД. Проверка сигнатуры файла — базовая защита, не полноценное антивирусное сканирование.

Деплой на публичный сервер, внешнее файловое хранилище, production CORS и финальная документация относятся к дням 8–9.
